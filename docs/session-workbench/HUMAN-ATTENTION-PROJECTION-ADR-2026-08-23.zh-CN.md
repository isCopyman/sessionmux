# 人类待处理入口：轻量投影，而不是收件箱

状态：已裁决；第一版已实现。

## 产品裁决

SessionMux 面向个人使用，不新增一套 Human Inbox 或“我的任务”。侧栏只提供一个稳定的
“待我处理”入口，把已经存在的两类状态汇总给人类：

1. Session/Room 中尚待目标 Session 回复的通信义务；
2. 看板中处于审核、阻塞等需要人类关注状态的任务。

入口只显示总数和两个来源摘要。点击后分别打开已有的会话中心“需要回复”筛选和任务看板
“需关注”视图。普通 Room 未读、Agent 间普通邮件、等待对方回复、已完成通知都不进入该入口。

## 数据与生命周期边界

- 不新增表，不复制消息或任务正文；计数始终由原事实源投影。
- 不增加“已处理”按钮或第二套状态机。回复义务在原通信链中清偿，任务关注在任务状态变化后消失。
- 会话中心仍负责查找和管理 Session；任务看板仍负责任务推进；“待我处理”不成为第三个工作中心。
- 看板范围请求通过轻量 UI 事件传给当前活动的 Board Tab；任务事实、过滤状态和 Board Tab
  持久化保持原有所有权。

## 暂缓项与扩展门槛

第一版不显示跨域逐条列表，因此不需要去重规则。将来只有在真实使用证明两个摘要不够时，才考虑
逐条投影；届时同一根因最多出现一行，优先连接到任务，其次连接到运行中的 Session，最后才是
裸通信事件。即使扩展，也不引入邮件文件夹、Human 身份表或另一套归档/已处理生命周期。

若未来加入 `@人类`，它应继续投影现有 Room/Mailbox 事件并跳回来源，而不是新建一份人类邮件。
