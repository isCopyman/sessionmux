## 1. 你需要的心智模型：双模规则

这是用户亲自拍板的设计决策，是理解整个 Claude profile 子系统的钥匙：

> **codeg 要么什么都不设（跟随 CLI），要么用 `--settings` 覆盖层统管。没有第三种状态。**

对应到代码（`src-tauri/src/commands/claude_profile.rs`）：

- `follow-default` → `:769` 提前返回，**一个字节都不写**
- 任何选中的 profile → `:773` 先清扫 profile 拥有的 env 键，`:779-786` 把三个
  `ANTHROPIC_*` 置空（空值 = 让 spawn 层 `env_remove`，挡住宿主 shell 继承的凭据），
  然后按 kind 挂 `--settings` 覆盖层

**已实测的事实**（别再重新推导）：

- 项目级 `.claude/settings.json` 优先级高于进程环境变量
- flag 层（`--settings`）上的 `ANTHROPIC_BASE_URL: ""` 既赢得合并、又被读成"未设置"
- Claude Code 的优先级：`managed > --settings > local > project > user`

### P0 —— CPA（managed profile）的模型下拉误导（已查清，待修）

用户截图发现：chip 显示 CPA，模型下拉却是官方那套 Opus/Fable/Sonnet/Haiku，
底下还有一条 **"You've reached your Fable 5 limit"**（官方额度报错）。

**磁盘上的实况**（`%APPDATA%\app.codeg\claude-profiles\imported.json`，
id=`imported`，label=`CPA`，kind=`managed`）：

```
ANTHROPIC_BASE_URL             = http://127.0.0.1:8317      ← 本地网关
ANTHROPIC_DEFAULT_OPUS_MODEL   = claude-opus-5[1m]
ANTHROPIC_DEFAULT_SONNET_MODEL = k3[1m]                     ← "Sonnet" 其实是 K3
ANTHROPIC_DEFAULT_HAIKU_MODEL  = deepseek-v4-flash[1m]
ANTHROPIC_DEFAULT_FABLE_MODEL  = claude-fable-5[1m]
ANTHROPIC_CUSTOM_MODEL_OPTION  = deepseek-v4-pro[1m]        ← 下拉里根本没这条
```

**我查到哪一步了（这一节我查完了，结论比最初的猜测精确得多）：**

先说被排除的两条弯路，别再走：

- ~~managed profile 的 `config_dir` 是 None，所以覆盖层没挂上~~ —— **错**。
  `config_dir_for_record` 对 managed 走 `materialize_managed_profile`
  （`claude_profile.rs:632-635`），返回 Some。覆盖路径**确实会被设上**。
- ~~适配器不认识 `extraArgs`，静默丢弃~~ —— **错**。装的是
  `@agentclientprotocol/claude-agent-acp` **0.69.0**（全局 npm 安装目录）：
  - `dist/acp-agent.js:4742` —— `const userProvidedOptions = sessionMeta?.claudeCode?.options`
    正是 codeg 送的那条路径
  - `:4870-4872` —— `extraArgs: { ...userProvidedOptions?.extraArgs, "replay-user-messages": "" }`
    → 进 CLI argv → `claude --settings <path>`

  **所以端点路由这条链是通的。**

另外，模型列表**不是前端写死的**：`deriveModelGroups`（`src/lib/model-config-groups.ts:117`）
的入参是 `SessionConfigOptionInfo`，即对端通过 ACP 上报的。

**真正的结论，三条：**

**(1) `ANTHROPIC_CUSTOM_MODEL_OPTION` 永远不会出现在 codeg 的下拉里，这不是 codeg 的 bug。**

它是 Claude Code **交互式 CLI** 的 `/model` 菜单特性。codeg 的下拉走的是完全另一条路：
适配器 `:5509` 用 `options: models.availableModels.map(...)` 构造 ACP 模型选项，
`models.availableModels` 是 **SDK 内置列表**，再被 settings.json 里的 `availableModels`
**allowlist 过滤**（`:4974-4979`）。注意 allowlist 只能**收窄**，不能**新增**——
那个 env 变量根本不喂这条链。

→ 该如实告诉用户：这个期待落空了，而且没法简单实现。真要做得走
`_meta.claudeCode.options.settings.availableModels`（适配器 `:4826-4835` 支持，
codeg 目前完全没填），但那**也只是 allowlist**，加不进网关独有的模型。

**(2) 真正该修、也修得了的：下拉不显示槽位重映射。**

CPA 把槽位重定向了——选「Sonnet」实际拿到 `k3[1m]`，选「Haiku」实际拿到
`deepseek-v4-flash[1m]`。下拉却显示官方名字加官方定价描述（"$10/$50 per Mtok"），
**这是主动误导**。codeg 知道这个映射（那份 settings.json 就是它自己写的），完全可以在行上
标注「Sonnet → k3[1m]」。纯增量 UI 改动，值得单开一条车道。

**(3) "Fable 5 limit" 那条红条，最可能是网关透传的上游错误，不是路由跑错。**

既然 `--settings` 链路是通的，会话应该在打 127.0.0.1:8317；网关转发上游、上游返回配额
错误、原样透传回来，就是这个现象。**但我没有确证。** 要坐实只有一个办法：
**查本地网关 127.0.0.1:8317 的访问日志**，看 codeg 的会话有没有打进去。
接手的人要给用户肯定答复的话，去查那个日志。
