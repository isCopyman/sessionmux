# dev 与 release 双实例的数据边界（O10 结案文档，2026-08-21）

> 起因：dogfooding 时 dev 实例建的群聊，用户在 release 实例里"看不见"，
> 一度误判为"同库但事件不互通"。实证更正后按台账 O10 立此文档。

## 一句话

**dev 和 release 不共库**：dev 用 `codeg-dev.db`，release 用 `codeg.db`
（同在 `%APPDATA%/app.codeg/` 下并存）。它们唯一的"共享"是**磁盘上的
agent 会话转录文件**——于是产生影子会话现象。

## 具体边界

| 数据 | 跨实例可见？ | 机制 |
|---|---|---|
| 会话（有磁盘转录文件的） | ✅ 会出现，但是"影子" | 双方都扫描 agent CLI 的转录目录并导入自己的库；对方实例建的会话会被本方扫描捡到，形成独立的库记录（影子会话） |
| Room / 群聊 | ❌ | 纯 DB 构造，只存在于建它的那个实例的库里 |
| Collection | ❌ | 同上 |
| 站内信 / 投递 / 徽标计数 | ❌ | 同上 |
| 工作台 / 页签布局 | ❌ | 同上 |
| work_task 待办任务 | ❌ | 同上 |
| 事件推送（WebSocket/Tauri 事件） | ❌ | 每实例只广播自己的事件，无跨进程通知 |

## 实用推论

1. **在 dev 里建群聊，release 永远看不见**——不是 bug，是库隔离。要给用户
   演示协作面，必须在同一个实例里操作。
2. **影子会话有迷惑性**：release 侧会"多出"dev 实例（乃至事故幽灵会话）的
   转录导入记录。看到来历不明的会话，先想"是不是另一个实例的影子"。
   （改进项：影子会话标注来源实例——未立项。）
3. **删除的语义是本库删除**：一方删掉影子会话不影响另一方的库记录，也不
   删共享的转录文件本体。
4. 双实例同时跑是 dogfooding 常态，安全；但**同一实例双开**（同一个 db 文件）
   不受支持。
